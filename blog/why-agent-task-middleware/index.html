为什么 AI Agent 需要任务协作中间件

从 Markdown 清单、权限边界、本地上下文和审计日志解释 TangoForge 的设计动机。

Agent
Local-first
MCP

AI 编码 Agent 已经足够强，可以接手真实开发任务。但围绕 Agent 的协作层仍然很薄。

TangoForge 的判断很简单：Agent 不应该只接收 prompt，它们应该通过带有状态、权限、上下文和审计日志的任务系统工作。

缺失的一层

很多 Vibe Coding 工作流从聊天窗口或终端开始。它很方便，但长期使用后很难回答这些问题：

  • Agent 现在到底在做哪一个任务？
  • 它读取了哪些上下文？
  • 哪些写操作是被允许的？
  • 任务推进之后具体改了什么？

TangoForge 把这些问题变成产品里的基础能力。

本地优先的控制权

本地守护进程让任务池和项目记忆保留在开发者自己的机器与项目目录里。对私有代码、早期产品实验和需要人工把关的开发流程来说，这比把所有上下文丢进聊天窗口更稳。
